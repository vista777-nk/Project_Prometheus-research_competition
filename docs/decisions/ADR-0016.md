# ADR-0016: 实验室服务器区分通告地址、监听地址与仿真自连入口

**状态**：已采纳

**日期**：2026-08-01

**决策者**：Phase 1.5 项目接手人、Codex

**关联**：[ADR-0006](./ADR-0006.md) 的静态地址规划；
[ADR-0014](./ADR-0014.md) 的 Ubuntu 20.04 / ROS Noetic 实测基线。

> ADR-0013 继续预留给超声波时序方案 A/B/C，本决策不得占用该编号。

---

## 背景

Phase 0 的 `server_only.launch` 在一台电脑上同时启动：

- `tcp_receiver.py` 服务端；
- `edge_server_bridge.py` 客户端；
- 其余 World Model / 研究占位节点。

默认网络配置的客户端目标与服务端 bind 都是 `127.0.0.1:9090`。这适合仿真闭环，
但在实验室服务器上运行它只能证明「服务器连回自己」，不能证明车机/无人机能够接入。

同一个 `server_ip` 还承担两种不同语义：边缘节点用它作为连接目标，服务器用它作为
bind 地址。把它改成 `0.0.0.0` 能让服务监听所有网卡，却会同时让客户端尝试连接
`0.0.0.0`；写成某块网卡的静态地址，又会在网卡未配置或改名时让服务直接 bind 失败。

接手时的真实服务器有 `192.168.3.30/24`，而 ADR-0006 的机器人隔离网规划为
`192.168.1.100/24`。未获授权前不能擅自改服务器网络，因此必须同时记录「现网可测」
与「机器人网尚未完成」，不能把前者冒充后者。

---

## 决策

### 决策 1：保留仿真入口，新增实机服务器入口

- `server_only.launch` 保持 Phase 0 单机仿真语义；
- `lab-server-real.launch` 只启动 TCP 接收端、World Model 与研究占位节点；
- 实机服务器入口不得启动 `edge_server_bridge` 或 `drone_car_bridge` 连回自己。

### 决策 2：通告地址与监听地址分离

`edge_server_tcp` 新增可选的 `server_bind_ip`：

- `server_ip`：边缘客户端连接的通告地址；
- `server_bind_ip`：服务器 socket 的本地监听地址；
- 旧配置没有新键时回退到 `server_ip`，保持仿真兼容。

实机配置使用 `server_ip: 192.168.1.100`、`server_bind_ip: 0.0.0.0`。监听全部网卡
不代表向公网开放；它仍受实验室网络边界与主机防火墙约束，边缘节点只应位于受控网段。

### 决策 3：Phase 1.5 服务器继续裸机运行

新增 `ROS_IP=<地址> make launch-server-real`。`ROS_IP` 必须显式给出，防止多网卡服务器
把不可达地址注册给 ROS Master。GPU/CUDA/模型权重方案尚属 Phase 2，
`Dockerfile.server` 继续明确构建失败，不提前制造一个看起来可部署的占位镜像。

### 决策 4：现网验证不关闭机器人网欠账

允许用当前 `192.168.3.30` 验证 ROS 注册、TCP 监听与协议解码；但只有在
`192.168.1.100` 实际配置、两台边缘节点可达且 chrony 同步通过后，才算机器人网部署完成。

## 被否决的方案

### 方案 B：继续使用 `server_only.launch`

否决。它会多启动一个边缘客户端连回本机，TCP 连接成功无法证明任何跨机器链路；
同时会让 `/car/server_connected` 产生误导性的真值。

### 方案 C：直接把 `server_ip` 改成 `0.0.0.0`

否决。`edge_server_bridge` 也读取该字段作为 `connect()` 目标；监听地址不是合法的远端
部署契约。把两种语义拆成两个键才不会在另一端制造新故障。

### 方案 D：把当前 `192.168.3.30` 写成机器人网最终地址

否决。它与 ADR-0006 和两台 Pi 的 `192.168.1.10/.20` 规划不一致；路由与隔离策略
尚未核实。当前地址只能作为本机实验记录，不能静默替代设计地址。

### 方案 E：立即实现服务器 GPU Docker 镜像

否决。Phase 1.5 只需要 ROS/TCP/World Model 基础服务，当前服务器上已有 3 张 RTX A6000，
但 CUDA 基线、推理框架和模型权重分发都没有决策。现在选镜像会把 Phase 2 研究栈提前固化。

---

## 验证

2026-08-01 在真实实验室服务器执行：

```bash
ROS_IP=192.168.3.30 make launch-server-real
```

结果：

- ROS Master 的 roslaunch 地址为 `192.168.3.30`；
- 仅有 `tcp_server`、`world_model`、`slam_node`、`eqa_engine`、`coordinator` 五个项目节点；
- `edge_server_bridge` / `drone_car_bridge` 均不存在；
- TCP 真监听 `0.0.0.0:9090`；
- 从 `192.168.3.30` 发送一帧 4-byte big-endian 长度前缀 JSON heartbeat 后，
  `/server/car/state` 收到并解码为 `robot_id: car`；
- 中止实验后 ROS 进程与 9090 监听均已清理。

真实 heartbeat 还抓到无 pose 时的全零无效四元数；修为单位四元数并加入回归后，
工作空间为 82 tests、0 error、0 failure、0 skip。

---

## 影响

- 服务器实机入口不再以 loopback 自连冒充跨机器部署。
- 网络配置可同时服务客户端目标与多网卡服务器监听。
- `make launch-server` 继续服务 Phase 0；实机必须使用 `make launch-server-real`。
- 机器人隔离网、chrony 与真实边缘节点接入仍是明确未完成项。
