# ADR-0013: 四路 HC-SR04 由底盘 MCU 定时并通过统一串口上报

**状态**：已采纳

**日期**：2026-08-02

**决策者**：Phase 1.5 项目接手人、Codex

**关联**：[ADR-0003](./ADR-0003.md)、[ADR-0009](./ADR-0009.md)、
[ADR-0018](./ADR-0018.md)

## 背景

确认 BOM 为两套互换底盘控制模块，每套均有 4 个 HC-SR04，且各自已有负责硬实时
运动控制的 MCU。旧骨架让 Raspberry Pi Python 节点直接产生 10 µs 触发脉冲；
Debian 非实时调度不能给这个时序作保证，而且会把底盘更换暴露到 Pi GPIO 接线。

## 决策

- MSPM0G3507 和 STM32F407VET6 各自负责本底盘四路 HC-SR04 的轮询、超时和串扰隔离；
- Pi 只通过与运动控制相同的 `/dev/mcu` 链路接收完整快照；
- 新增 `CMD_ULTRASONIC=0x14`，DATA 固定为 `front,rear,left,right` 四个小端
  `uint16` 毫米值，`0xFFFF` 表示该方向当前不可用；
- Pi 桥把四个值转换为现有四路 `sensor_msgs/LaserScan`，保持上层接口不变；
- 实机入口必须同时验证 PONG 身份/固件版本和至少一帧超声波快照，缺失时失败关闭；
- 具体 TRIG/ECHO 引脚、电平转换和轮询间隔必须由电子组接线表确认，现阶段移植层返回
  “不可用”，不得编造可烧录完成状态。

## 后果

删除 Pi 侧 `hcsr04_driver.py` 与 GPIO 抽象。两种底盘共享同一 Pi 协议实现，机械换装
不再要求改 Pi GPIO。代价是 MCU 引脚和计时器资源增加，且正式固件仍需上板完成
TRIG/ECHO 映射与回波定时器验收。

## 验证

- 两份 C 协议测试均覆盖 0x14 载荷；
- Pi 纯 Python 测试覆盖顺序、单位、`0xFFFF` 和启动失败关闭；
- 串口自测用同一生产解析器验证 PONG 与超声波帧。
