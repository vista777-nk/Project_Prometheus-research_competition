# ADR-0020: 分支模型：dev 为集成主线，main 为备份与发布线

**状态**：提议（等待负责人采纳；采纳前不改 CONVENTIONS.md、CI 配置或任何分支）

**日期**：2026-11-06

**决策者**：接手团队成员（2026-11-06 会话中答复了分支方向，答复由 Claude 转述）、Claude（起草）；采纳需负责人 @vista777-nk 确认

**关联**：[CONVENTIONS.md](../../CONVENTIONS.md) §1.1、[PROTOCOL.md](../ai-collaboration/PROTOCOL.md) §10、[CLAIMS.md](../ai-collaboration/CLAIMS.md) 的 T-001、T-008、T-012

## 背景

- CONVENTIONS.md §1.1 把 `main` 写成稳定主线，功能分支合回 `main`。
- 实际开发在 `dev` 上进行。2026-11-06 接手时，本机克隆里 `main` 与 `origin/main` 都在 `a0b7243`，`git rev-list --left-right --count main...dev` 得到 `0 112`：`dev` 比 `main` 多 112 个提交，`main` 没有 `dev` 没有的提交。
- CLAIMS T-008 与交接书 §2.4 写过「`main` 已快进到 `dev`」，但当天 `git ls-remote` 看到远端 `main` 仍是 `a0b7243`。
- CI 对所有分支的 push 都触发，`pull_request` 只对 `main` 触发，所以 PR 目标是 `dev` 时只有 push 触发。
- PROTOCOL §10 第 1 项把「集成分支用 `dev` 还是 `main`」列为待负责人确认。

## 决策

以下四点是团队成员 2026-11-06 的答复，这里是转述：

1. `dev` 是主线开发分支（集成分支）。新工作分支从 `dev` 切出，合回 `dev`。
2. `main` 用于备份与发布，不在 `main` 上开发。
3. 其余分支，除非承担重要的过渡作用，都可以处理。
4. 将来无人机与无人车的代码库一定会分化，到时可能需要分开的开发分支。

## 起草时补充的内容（未经确认）

为让上面四点能执行，起草时加了下面几条，采纳前请逐条确认或删改：

1. `main` 的更新方式：只由负责人在备份或发布点，把一个 CI 全绿的 `dev` 提交快进到 `main`，AI 不推送 `main`；发版 tag 从 `main` 打（沿用交接书 §2.4）。
2. 处理第 3 点所说的分支时，逐个确认，删除前记录分支名与 SHA，并保留一份可还原的备份（例如 `git bundle`）。`exp/` 分支沿用 CONVENTIONS.md §1.1「不能删除」的规定，除非另有决定。
3. 第 4 点不预设分支命名，也不现在创建；出现具体拆分时由新的 ADR 补充。
4. CI 的 `pull_request` 只对 `main` 触发。若 PR 目标是 `dev`，建议把 `dev` 也加进去。这会改变门禁，不在本 ADR 里改，采纳后单独提交并由负责人审查。
5. 谁点合并按钮、纯文档改动能否由 AI 合并，仍是 PROTOCOL §10 第 2、3 项，本 ADR 不决定。
6. GitHub 上的默认分支：2026-11-06 经公开 API 读取是 `dev`，与本决定一致。API 对 `dev` 和 `main` 都返回 `protected=false`，这个标志不一定反映 ruleset；是否启用分支保护，请负责人在 GitHub 设置页核对并决定。

## 备选方案

- 保持 CONVENTIONS.md 原状（`main` 为主线）：与实际不符，要把 112 个提交合入 `main`，而 `main` 按该文档的铁律不能直接推送。没有选。
- 改回 `main` 做集成分支：同样要合入 112 个提交，还要改默认分支。答复没有选这条。
- 现在就按载体（无人机、无人车）拆长期分支或拆仓库：目前两边共用 `air_ground_interfaces` 和部署代码，没有这个需要。将来再议。

## 后果

- 文档与实际一致，PR 目标明确，`main` 成为可回溯的快照。
- 采纳后要同步 CONVENTIONS.md §1.1、PROTOCOL.md §2.2 与 §10、CONTRIBUTING.md、CHANGELOG.md 里「待 ADR-0020 固化」的表述，并决定 CI 的 `pull_request` 范围。
- 在第一次发布点之前，`main` 落后 `dev` 112 个提交，不代表最新代码。
- 没有验证：GitHub 上实际生效的保护规则（只读到 API 的 protected 标志）；采纳后第一次把 `dev` 快进到 `main` 的流程。
