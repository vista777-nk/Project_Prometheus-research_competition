# ADR-0017: 跨校区部署只跨越受控 TCP 隧道，服务器本地 ROS 常驻运行

**状态**：已采纳

**日期**：2026-08-01

**决策者**：Phase 1.5 项目接手人、Codex

**关联**：[ADR-0007](./ADR-0007.md) 的外网重估触发条件；
[ADR-0016](./ADR-0016.md) 的服务器真实入口。

> ADR-0013 继续预留给超声波时序方案 A/B/C。

---

## 背景

机械与电子硬件将在良乡校区组装，GPU 服务器位于中关村校区，且负责人明确指出
两地远程连接可能不稳定。这触发了 ADR-0007 的 T1：原先同一实验室隔离网内的
网络假设不能继续原样使用。

原规划让两台 Pi 把 `ROS_MASTER_URI` 指向服务器。ROS 1 除 11311 外，还会让每个
节点监听随机 XML-RPC/TCPROS 端口并由节点间直连；跨校区链路、NAT 或短暂断线都会
让这种拓扑难以恢复。与此同时，当前 edge↔server TCP JSON 协议虽然有长度边界和
重连机制，却没有 TLS、客户端认证或消息签名。直接把 9090 暴露到校园网会让任何
可达者注入状态，未来下行命令启用后风险更高。

服务器接手审计还发现两个运维问题：真实入口只能从终端手工启动；根分区使用率
97%，而 `/data2` 仍有约 1.1 TiB 可用空间。远程不稳定时，服务必须能自己恢复，
日志也不能继续增长在根分区。

---

## 决策

### 决策 1：跨校区不传 ROS，只传单一受控 TCP 端点

- 服务器 ROS Master 与五个服务节点只在服务器本机通信，默认
  `ROS_MASTER_URI=http://127.0.0.1:11311`、`ROS_IP=127.0.0.1`；
- `network_server.yaml` 默认让 TCP 接收端只监听 `127.0.0.1:9090`；
- 良乡端以后通过经学校网络负责人批准的 VPN 或 SSH 隧道进入该回环端口；
- 在隧道方案、端点地址和防火墙范围确认前，不提交任何真实地址、口令或密钥；
- `network_lab.yaml` 保留给三机确实位于同一受控隔离网时使用，不作为跨校区默认。

这样，短时断线只影响一个带退避重连的 TCP 会话，不会破坏两端各自的 ROS 图。
边缘侧 ROS Master 的最终位置和隧道端点仍需结合更新后的硬件/网络参数另行决定。

### 决策 2：服务器使用 systemd 常驻，不依赖远程终端

新增模板服务 `air-ground-lab-server@.service`：

- 以指定普通用户运行当前 Catkin 工作空间；
- 启动后联合检查五个必需节点与 TCP 监听；
- 五个节点在真实入口中全部 `required=true`；
- `Restart=always`，覆盖 roslaunch 因 required 节点退出却返回 0 的情况；
- ROS 日志写入 `/data2/air-ground-server/ros-log`；
- 五分钟 timer 重复运行健康检查，结论进入 journald。

安装器只在配置不存在时创建 `/etc/air-ground/server.env`，重复安装不覆盖本机值。

### 决策 3：服务器时间源暂不切换到良乡车机

当前服务器的 `systemd-timesyncd` 已显示时钟同步。跨校区链路不稳定时，让服务器
chrony 依赖良乡车机会放大故障，因此现在不替换系统时间服务。硬件上线后必须同时
记录服务器与两台 Pi 相对同一参考源的偏差；若良乡现场离线，再决定现场车机主时钟
与服务器外部 NTP 之间的实验对齐办法。

## 被否决的方案

### 方案 B：把服务器 ROS Master 直接暴露给两台 Pi

否决。只开放 11311 不够，ROS 1 节点随机端口仍需双向可达；断线后的半失效注册也
很难可靠恢复。这不适合跨校区链路。

### 方案 C：把 `0.0.0.0:9090` 直接开放到校园网

否决。现协议没有传输加密与对端认证，违反 SECURITY.md 的远程访问前置条件。
即使校园地址不是公网，也不能把可达性当成认证。

### 方案 D：现在选择并安装具体 VPN 产品

否决。学校网络策略、良乡出口方式和硬件网络参数尚未确定。先锁定“受控隧道”这一
安全边界；具体实现由后续参数决定，避免提前固化一个现场不可用的产品。

### 方案 E：立即改用服务器 Docker 镜像

否决。GPU/CUDA/模型栈仍属于 Phase 2；当前 ROS/TCP 服务裸机依赖已实测，重做镜像
不能改善跨校区可靠性，反而引入尚未决定的运行时。

---

## 验证

- `test_server_deployment.py` 覆盖健康/缺节点/误启动本地客户端、回环默认值、
  required 节点、systemd 恢复语义与远程 ROS 负向拒绝；
- 当前用户 `Linger=yes`，用户 systemd 服务与五分钟 timer 已实机安装、enabled、active；
- `rosnode kill /world_model` 后 MainPID 改变、`NRestarts=1`，五个节点和 TCP 自动恢复；
- 常驻端真实 heartbeat 解码得到 `robot_id=car`、单位四元数；
- `ss` 确认 11311/9090 均只监听 `127.0.0.1`；
- 系统 Python 跑部署校验为 52 通过、0 失败、0 跳过，10 个 systemd 单元通过。

---

## 影响

- ADR-0016 的 `0.0.0.0:9090` 仍是同一受控实验室网的已验证能力，不再是跨校区默认；
- 服务器重启或 SSH 会话中断不会终止项目服务；
- 硬件参数更新只需补边缘端配置与受控隧道，不需要重新改服务器 ROS 拓扑；
- Phase 1.5 仍不能在隧道和真硬件到位前关闭。
