## Step 1: 实机组装 + 仿真对齐（2026.08）

### 硬件基线与装配顺序

完整数量和待确认参数统一维护在
[Phase 1.5 实机硬件基线](../docs/experiments/phase-1.5-hardware-baseline.md)，
不再在路线图复制一份会漂移的采购表。冻结的五个模块是：

1. 共享车载智能载荷：Pi 5 + ICM42688 + A2M12 + 云台/OpenMV；
2. 差速控制模块：MSPM0 + 2×MC520P30 + 2×DRV8871 + 4×HC-SR04 + IA6B；
3. 麦轮控制模块：STM32F407 + 4×MC520P30 + 4×DRV8871 + 4×HC-SR04 + IA6B；
4. 无人机视觉载荷：D435i CB 或双 Raspberry Pi Camera；
5. 无人机本体：Pi 5 + Pixhawk 6C/PM07/M9N + F450 + 915 MHz 数传 +
   A2212/BL32/1045 动力系统。

按“控制模块空载台架 → 低压/限流电机台架 → 底盘离地 → 共享载荷 →
无人机无桨 → 系留/保护区实飞”的顺序推进。共享车载载荷只有一套，两底盘不安排
同时完整运行。

### 本阶段目标

- [ ] 无人机可手动悬停 5 分钟以上
- [ ] 差速底盘可由 IA6B 遥控，MSPM0 编码器闭环和四路超声波可用
- [ ] 麦轮底盘可由 IA6B 遥控，STM32 编码器闭环和横移可用
- [ ] 空中 915 MHz 电台经 Pixhawk TELEM1 与地面站互收 MAVLink 心跳
- [ ] Pi 经 Pixhawk TELEM2 运行 MAVROS；D435i 模式发布 RGB/深度/点云
- [ ] 共享载荷在两底盘间换装后，PONG 身份和所有传感器健康检查均通过
- [ ] 仿真参数校准到与实机一致（传感器噪声、延迟、带宽）
- [x] **VLM 图像传输边界确定**：915 MHz 数传只承载 Pixhawk↔地面站的
  MAVLink；图像走受控 IP 链路/TCP，不把未知电台型号的吞吐写死为 24 KB/s。
- [ ] **时钟同步**：实机三台设备部署 chrony，车机作为 NTP server。仿真无需处理。

## Step 2: EQA 系统初步实现（2026.09~12）

### 研究问题

> 给定一个自然语言查询（如 "Where is the red ball?"），系统协调无人机和地面车进行空地联合探索，最终给出答案。

### 技术栈

| 模块 | 方案 |
|------|------|
| VLM | LLaVA-1.6 / InternVL2 (实验室服务器 GPU) |
| SLAM | RTAB-Map (RGB-D + LiDAR) 或 SLAM Toolbox |
| 空地联合标定 | AprilTag 地面标记 + 无人机俯瞰定位 |
| 任务规划 | 基于 LLM 的 hierarchical planning |
| 通信 | 915 MHz Pixhawk↔地面站 MAVLink + 受控 IP 隧道/TCP |

### 里程碑

- [ ] VLM 可回答基于单张图片的简单问题
- [ ] 车机可自主导航到指定坐标
- [ ] 无人机可自主起飞→悬停→降落
- [ ] 空地联合：无人机俯瞰引导车机导航
- [ ] EQA Demo: "红色球在哪里？" → 空地联合搜索 → 返回坐标

## Step 3: 竞赛（2027.01~08）

### 全国电赛 (TI杯)

- **时间**：2027 年 5~6 月（预计）
- **平台**：车机 + 差速底盘
- **合规要点**：MSPM0G3507 为主控；树莓派/STM32 为协处理器（仅做数据预处理，不参与控制决策）
- **准备**：提前准备好"电赛合规模式"代码分支，禁用远程通信

### CRAIC2027 空地协同赛道

- **时间**：2027 年 7~8 月（预计）
- **平台**：无人机 + 车机 + 麦轮底盘
- **优势**：EQA 系统直接支撑；服务器架构通常允许外部算力

## Step 4: 世界模型入门研究 → 毕设（2027.07~2028.06）

### 研究方向（按优先级）

1. **空地联合 3D 场景重建**
   - 无人机俯瞰视角 + 车机地面视角融合
   - 3D Gaussian Splatting (3DGS) 实时重建
   - 语义注入 (用 VLM 标注 3D 高斯)

2. **动作条件化未来预测**
   - "如果我移动到这里，会看到什么？"
   - 基于 Diffusion / Video Prediction 的 world model
   - 在仿真中先验证，再迁移实机

3. **Embodied World Model**
   - DreamerV3 风格：学习紧凑的 latent dynamics
   - 在"想象"中进行 planning

### 关键文献

- 3D Gaussian Splatting (Kerbl et al., 2023)
- DreamerV3 (Hafner et al., 2023)
- UniSim (Yang et al., 2024)
- LeRobot (Cadene et al., 2024)

## 风险与应对

| 风险 | 概率 | 应对 |
|------|:---:|------|
| 实机组装进度延迟 | 中 | 8 月集中完成；仿真先行验证所有软件逻辑 |
| 树莓派5 性能不足以跑 VLM 边缘推理 | 高 | 已确认 VLM 放服务器；电赛备降级方案 (MobileNet+传统CV) |
| 电赛不允许联网 | 高 | 提前准备 MSPM0G3507 独立运行分支 |
| 无人机炸机 | 中 | 仿真充分验证后再实飞；备桨备电机 |
| F450 起飞重量/推重比不足 | 中 | 无桨称重与台架推力验收；视觉载荷可切换为双 Pi Camera |

## 待重估的技术决策（Phase 2 动手前必查）

Phase 1 有几处决策是在"当前规模下正确、但换了条件就不对"的前提下做的。
条件变化往往发生在别的工作里，没人会主动回来读 ADR——所以把触发条件
挂在这里，作为 Phase 2 开工前的检查项。

| 触发条件 | 要重估什么 | 出处 |
|---------|-----------|------|
| 边缘节点网段**接外网**，或 Pi 上出现监听 `0.0.0.0` 的非 ROS 服务 | `network_mode: host`——容器可达宿主机 loopback 服务，风险从内网横向升级为公网可达 | [ADR-0007](../docs/decisions/ADR-0007.md) §决策-3 T1 |
| **迁移到 ROS 2** | 同上。DDS 有可配置端口范围，`bridge` 变得可行，host 模式的理由消失。**最容易发生的事是把 compose 原样搬过去** | ADR-0007 §决策-3 T2 |
| 同一台 Pi 上跑**第二个互不信任的负载**（如第三方视觉模型容器） | 同上。host 模式下两者共享 netns，网络上毫无隔离。届时 macvlan 是首选 | ADR-0007 §决策-3 T3 |
| 引入 **Watchtower 或任何自动更新** | 必须同时加上"飞行/实验期间不自动更新"的时间窗约束 | [ADR-0005](../docs/decisions/ADR-0005.md) §决策-5 |
